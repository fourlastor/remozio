# Remozio agent workflow

Use the repository's [babysit-pr skill](.agents/skills/babysit-pr/SKILL.md) for every open PR. Its watcher is the readiness authority. Follow its review triage, batching, and cleanup rules.

Before each push, build and run the tests that you added or changed. CI on a PR is a fast sanity check. It runs only the jobs whose inputs the PR changes. In the Mac core tests job, it runs only the macos/core test classes that the PR adds or changes, plus a small smoke set; `scripts/ci-pr-jobs.py` describes when it runs the full suite instead. In the Mac build job, a PR builds only the Debug app unless it changes the app, the release-signing experiment, a Swift package manifest or a shared build input. The full CI matrix runs every night on main, and it covers every `./scripts/check-local.sh` step on both hosts. If a nightly run fails, fix main before any other work. `./scripts/check-local.sh` runs the repository checks and portable Kotlin/Android tasks on both hosts, the shared Swift protocol and host suites on Linux, and the native Mac builds/tests plus `:phone-core:approvalFlowTest` on macOS. The Mac interoperability peers are not executable on Linux; when CI runs the Mac build and interoperability jobs for a PR, they must pass before merge. Use Python 3.11 or later on Linux and 3.13 or later on macOS (the Mac fixture cleanup calls `os.waitid`, which CPython provides on macOS from 3.13), JDK 21, Swift 6.2 or later on Linux, and set `ANDROID_HOME` to an Android SDK with platform 37.0 and build tools 37.0.0. macOS needs the supported Xcode toolchain. When the XPC experiment changes, also run its live checks on a supported Mac GUI session and retain the evidence. CI builds and unit tests do not substitute for live experiment results.

Keep PRs focused. Record what an experiment proves and what remains untested. Do not collect secrets in committed evidence. Device-dependent end-to-end checks wait for the user's interactive session.
